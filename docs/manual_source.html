1한 장 요약

굿즈 트렌드는 쇼핑몰·리셀 마켓·커뮤니티를 매일 둘러보고, 굿즈 종류(응원봉, 인형, 키링 …)별로 “지금 평소보다 얼마나 뜨고 있는가”를 핫지수 0~100점으로 보여주는 서비스입니다.

질문답
무엇을 알려주나?요즘 뜨는 굿즈 종류의 순위와 점수, 그리고 그 이유. (BTS 응원봉·aespa 응원봉 → 모두 ‘응원봉’ 하나로 집계)
어디서 정보를 모으나?애니메이트(판매인기순), KREAM(리셀 시세·거래 수), 디시인사이드(굿즈·아이돌 갤러리 17곳). 키를 받으면 쿠팡·유튜브·네이버 쇼핑도 연결 가능
“핫하다”의 기준은?많이 팔리는 것이 아니라 평소보다 늘어난 것. 최근 7일을 그 이전 28일과 비교합니다
점수는 어떻게?7가지 신호를 재고 → 다른 종류와 비교해 얼마나 튀는지로 바꾸고 → 중요도를 곱해 더한 뒤 → 0~100점으로 환산
새로운 굿즈는?사전에 없는 단어가 갑자기 많이 나오면 ‘새로 뜨는 단어’로 따로 알려줍니다 (예: 말랑이, 젤리캣)
언제 갱신되나?매일 한국 시간 오전 9시 17분부터 시도해 하루 1번 집계. 약 3분 소요
어디서 보나?웹 주소 하나로 폰·컴퓨터 모두. 폰에서는 ‘홈 화면에 추가’로 앱처럼 사용
비용은?현재 0원 (GitHub·Supabase·Vercel 무료 범위)
한 줄 비유 — 매일 아침 시장 조사원이 여러 가게(쇼핑몰)와 동네 수다방(커뮤니티)을 돌아보고, “어제까지 조용하던 인형 코너에 오늘 사람이 몰렸다”는 걸 점수와 근거가 적힌 보고서로 정리해 주는 것과 같습니다.

2어떤 문제를 푸는가

사람이 직접 하면 생기는 문제

문제설명이 서비스의 해결
정보가 흩어져 있다판매 순위는 쇼핑몰에, 시세는 리셀 마켓에, 반응은 커뮤니티에 있다여러 곳을 한 번에 모아 같은 기준으로 비교
“원래 큰 것”에 가려진다응원봉처럼 늘 많이 팔리는 것이 항상 1등 → 새로 뜨는 것이 안 보인다절대량이 아닌 변화량으로 점수화
감으로 판단한다“요즘 이게 뜨는 것 같아”는 근거를 대기 어렵다점수마다 어떤 신호가 몇 점을 올렸는지 표시
모르는 것은 못 찾는다내가 아는 키워드로만 검색하면 새로운 유행을 놓친다베스트 순위를 통째로 보고, 사전에 없는 단어를 따로 감시
매일 하기 힘들다조사는 반복 노동매일 자동 실행
왜 ‘종류’ 단위인가? 개별 상품(예: “BTS 응원봉 ver.4”)은 출시·품절에 따라 금방 생겼다 사라져 추세를 보기 어렵습니다. ‘응원봉’, ‘인형’ 같은 종류 단위는 꾸준히 존재하므로 날짜별로 비교가 가능하고, 상품 기획·재고 판단처럼 실제 의사결정에 쓰기 좋습니다. 각 종류 옆에는 요즘 순위가 높은 실제 상품명을 예시로 붙여, 구체적인 상품도 함께 볼 수 있습니다.

4하루의 작동 순서

  1. 깨어나기 (09:17~) — GitHub 예약 실행은 몇 시간씩 늦거나 빠질 수 있어, 한국 시간 09:17부터 23:17까지 2시간마다 시도합니다. 그날 처음 도착한 실행만 일하고, 나머지는 “오늘 이미 했음”을 확인하고 30초 안에 끝납니다.
  2. 수집 (약 2분) — 사이트를 돌며 정보를 가져옵니다. 사이트에 부담을 주지 않도록 요청 간격을 둡니다(애니메이트 10초, KREAM 5초, 디시 약 3초에 1번). robots.txt(사이트가 정한 수집 허용 규칙)가 금지한 곳은 가져오지 않습니다.
  3. 분류 — 상품명·글 제목에서 굿즈 종류를 찾습니다 (5장).
  4. 저장 — 창고(Supabase)에 묶음으로 저장합니다. 상품 수백 개를 60번 정도의 요청으로 저장해 빠릅니다.
  5. 점수 계산 (약 10초) — 7가지 신호 → 핫지수 (6~8장).
  6. 새 아이템 감시 — 급상승 종류와 새로 뜨는 단어를 찾아 저장합니다 (9장).
  7. 상태 점검 — 어떤 사이트에서 수집량이 평소의 30% 아래로 떨어졌는지 확인합니다(사이트 구조가 바뀌었을 가능성).
  8. 화면 반영 — 웹 화면은 열 때마다 창고의 최신 결과를 읽으므로, 집계가 끝나는 즉시 새 순위가 보입니다.

67가지 신호 — 무엇을 재는가

‘핫하다’는 하나의 숫자로 잴 수 없습니다. 그래서 서로 다른 각도에서 7가지를 잽니다. 모든 신호의 공통 원칙은 하나입니다.

원칙: 얼마나 많은가(절대량)가 아니라, 최근 7일이 그 이전 28일보다 얼마나 늘었나(변화량)를 잰다.
왜 변화량인가? 절대량으로 재면 원래 시장이 큰 응원봉이 매일 1등이고, 막 뜨기 시작한 종류는 묻힙니다. 우리가 알고 싶은 건 “지금 평소보다 뜨고 있는 것”입니다. 왜 7일 대 28일인가? 7일은 요일 효과(주말에 글이 많음)를 평균내기 위한 최소 단위이고, 28일(4주)은 ‘평소’를 안정적으로 정의할 만큼 길면서 계절 변화를 너무 늦게 따라가지 않는 길이입니다.

변화율을 재는 공통 공식

변화율 = ln( (최근 7일 하루 평균 + ε) ÷ (이전 28일 하루 평균 + ε) )
ln = 자연로그, ε(엡실론) = 1 (점유율은 0.02)

왜 나누기에 ln(로그)을 씌우나? 그냥 나누면 2배 증가는 2, 절반 감소는 0.5로 증가와 감소가 비대칭입니다. 로그를 씌우면 2배 = +0.69, 절반 = −0.69로 대칭이 되고, 0은 ‘변화 없음’이 됩니다. 또 10배·100배 같은 극단값이 점수를 독차지하지 않게 눌러 줍니다.
왜 ε를 더하나? 평소 0건이던 것이 1건이 되면 나누기가 무한대가 됩니다. 작은 수 ε를 양쪽에 더해 “0 → 1건”같은 작은 변화가 과장되지 않게 합니다.

#신호재는 것과 계산의미 / 출처중요도
1베스트 순위 점유율판매인기 상위 20칸 중 이 종류가 차지한 비율의 변화율. 하루 여러 번 수집하면 회차 평균실제로 팔린다 / 애니메이트·쿠팡1.5
2커뮤니티 언급량굿즈 언급 글 수의 변화율. 글마다 가중치 1 + ln(1+추천·댓글)/3 — 반응 많은 글은 최대 몇 배까지만 더 셈사람들이 이야기하기 시작 (판매보다 먼저 반응) / 디시·유튜브1.2
3리셀 거래 속도KREAM 누적 거래 수의 하루 증가량 → 최근 7일 vs 이전 기간 변화율웃돈 주고도 산다 / KREAM1.2
4품절 비율최근 3일 정가 판매 상품 중 품절 비율 (0~1). 변화율이 아닌 현재 상태공급이 수요를 못 따라감 / 품절 표시가 있는 쇼핑몰1.2
5리셀 매물새로 보이기 시작한 리셀 상품 수의 변화율되팔 만큼 수요가 있다 / KREAM1.0
6리뷰 증가정가 판매처 누적 리뷰 수의 하루 증가량 변화율실제 구매가 늘었다 / 리뷰 수가 있는 쇼핑몰0.8
7판매처 증가검색 결과 상품 수의 변화율파는 곳이 늘었다 (늦게 따라옴) / 네이버 쇼핑0.5
중요도(가중치)를 이렇게 정한 이유 — 실제 지갑이 열렸다는 직접 증거(베스트 점유율 1.5)를 가장 높게, 웃돈·품절·말처럼 수요가 공급을 앞선다는 증거(1.2)를 다음으로, 간접 증거(리셀 매물 1.0, 리뷰 0.8)를 그다음, 판매자가 뒤따라 늘리는 늦은 신호(판매처 0.5)를 가장 낮게 두었습니다. 이 값은 상식에 기반해 정한 초기값이며, 데이터가 몇 달 쌓이면 “실제로 유행한 종류를 가장 잘 맞힌 가중치”로 다시 맞출 계획입니다(12장).

현재 실제로 데이터가 들어오는 신호: 1·2·3·5 (애니메이트·KREAM·디시). 4·6·7은 해당 정보를 주는 소스(품절 표시·리뷰 수가 있는 쇼핑몰, 네이버 쇼핑)를 연결하면 자동으로 채워집니다.

7점수 계산 — 수식과 이유

7가지 신호는 단위가 제각각입니다(비율, 로그 변화율, 0~1). 이걸 하나의 점수로 합치려면 같은 잣대로 바꿔야 합니다. 3단계로 계산합니다.

1단계 · 표준화: “다른 종류들보다 얼마나 튀나?”

z = (내 값 − 중앙값) ÷ (1.4826 × MAD)
중앙값 = 모든 굿즈 종류의 값을 줄 세웠을 때 가운데 값
MAD = 각 값이 중앙값에서 떨어진 거리들의 중앙값 (‘보통 얼마나 흩어져 있나’)
z 는 −4 ~ +4 로 자릅니다
쉽게 말하면 — 반 학생들 키를 볼 때 “175cm”보다 “반 평균보다 표준적인 차이의 2배만큼 크다”가 더 많은 걸 알려줍니다. z는 “이 신호에서 이 종류가 보통의 차이 몇 개만큼 튀는가”입니다. z = 0이면 보통, +2면 꽤 높음, −2면 꽤 낮음.
왜 평균·표준편차가 아니라 중앙값·MAD인가? 평균은 극단값 하나에 끌려갑니다. 예를 들어 한 종류만 언급이 50배 폭증하면 평균과 표준편차가 커져서 나머지 모두가 0 근처로 뭉개집니다. 중앙값과 MAD는 극단값의 영향을 거의 받지 않아(‘robust z-score’), 폭증한 종류는 확실히 높게, 나머지는 서로 구별되게 남습니다. 1.4826은 데이터가 정규분포일 때 MAD를 표준편차와 같은 크기로 맞춰 주는 상수입니다. ±4로 자르는 이유는 신호 하나가 혼자 점수 전체를 결정하지 못하게 하기 위해서입니다.

2단계 · 가중 평균: 종합 점수

종합 점수 = Σ (중요도ᵢ × zᵢ) ÷ Σ 중요도ᵢ
Σ 중요도 = 1.5+1.2+1.2+1.2+1.0+0.8+0.5 = 7.4 (항상 7개 전체로 나눔)
데이터가 없는 신호는 z = 0(중립)으로 취급
왜 없는 신호를 0으로 두고 7.4 전체로 나누나? 근거가 적은 종류가 신호 1~2개만으로 극단적인 점수를 받지 않게 하려는 장치입니다. “증거가 부족하면 평범한 쪽(0)으로 본다”는 보수적 원칙이죠. 대신 화면에 근거 수(coverage)를 함께 표시해 몇 개의 신호로 낸 점수인지 알 수 있게 합니다.

3단계 · 핫지수: 0~100점으로 환산

핫지수 = 100 ÷ (1 + e−1.5 × 종합 점수)
e ≈ 2.718. 종합 점수 0 → 50점, +1 → 82점, −1 → 18점

그림 1. 종합 점수(가로)와 핫지수(세로)의 관계. 가운데는 민감하게, 양 끝은 완만하게 바뀌는 S자 곡선입니다.

왜 S자 곡선(로지스틱 함수)인가? ① 어떤 점수가 들어와도 결과가 반드시 0~100 사이에 들어옵니다. ② ‘평소’(0)가 정확히 50점이 되어 직관적입니다. ③ 평범한 구간에서는 작은 차이도 잘 드러나고, 이미 아주 높은 구간에서는 더 올라도 점수가 조금씩만 늘어 “100점 넘는 이상한 숫자”가 생기지 않습니다. 1.5는 곡선의 기울기로, 종합 점수 ±1(보통의 1배 차이)이 대략 82점/18점이 되도록 정했습니다.
핫지수표시뜻
85 ~ 100🔥 급상승평소보다 확실히 뜨고 있음 (종합 점수 약 +1.15 이상)
70 ~ 84📈 상승뜨는 중 (약 +0.56 이상)
31 ~ 69➖ 보합평소 수준
16 ~ 30📉 하락식는 중
0 ~ 15🧊 급하락확실히 식고 있음

덤 · “왜 이 점수인가” (기여 점수)

신호 i 의 기여 점수 = (중요도ᵢ × zᵢ ÷ 7.4) ÷ 종합 점수 × (핫지수 − 50)
모두 더하면 정확히 ‘핫지수 − 50’ (반올림 오차 ±1)

핫지수가 50점에서 얼마나 벗어났는지를, 각 신호가 종합 점수에 보탠 비율대로 나눠 가진 것입니다. 그래서 “인형 96점 = 50 + 품절 12.6 + 언급량 11.0 + …”처럼 점수를 근거별로 분해해 보여줄 수 있습니다.

9새 아이템이 떠오를 때

순위(6~8장)는 이미 아는 종류끼리의 비교입니다. 새로운 유행을 놓치지 않으려고 두 개의 감시 장치를 따로 둡니다.

감시 ① 언급량 급상승 — “평소와 다른 날” 알림

최근 = 최근 3일 하루 평균 언급 수
평소 = 7일 전 ~ 35일 전 하루 평균 (μ), 흩어짐 = 표준편차 (σ)
z = (최근 − μ) ÷ ( max(σ, √μ, 1) ÷ √3 )
조건: z ≥ 3 그리고 최근 하루 평균 ≥ 3건 → ‘급상승’

그림 2 (설명용 숫자). 파란 막대 = ‘평소’ 기간, 회색 = 비교에서 빼는 완충 기간(최근 4~7일 전), 빨강 = ‘최근 3일’. 평소 평균 3.0건/일 → 최근 3일 평균 13.3건/일, z ≈ 10 → 급상승.

설계 이유
• 왜 3일? 하루치만 보면 우연히 튄 날과 구별이 어렵고, 며칠에 걸쳐 오르는 상승도 놓칩니다. 3일 평균은 우연을 줄이면서 빠르게 반응합니다.
• 왜 최근 4~7일 전은 빼나? 상승 초반이 ‘평소’에 섞이면 평소 기준이 같이 올라가 급상승이 덜 튀어 보입니다. 완충 기간을 두어 이를 막습니다.
• 왜 √μ와 1을 바닥으로? 글 수처럼 ‘세는’ 데이터는 원래 평균의 제곱근만큼 자연스럽게 흔들립니다(포아송 분포의 성질). 하루 0~1건인 조용한 종류가 2건이 됐다고 경보가 울리지 않게 최소한의 흔들림을 보장합니다.
• 왜 ÷√3? 3일을 평균내면 우연한 흔들림이 √3배 줄어듭니다. 그만큼 기준을 정밀하게 잡습니다.
• 왜 z ≥ 3? 평소라면 우연히 이 정도로 튈 확률이 매우 낮은(약 0.1%) 수준이라, 경보가 남발되지 않습니다.

감시 ② 새로 뜨는 단어 — 사전에 없는 굿즈 찾기

종류를 분류하지 못한 상품명·글(5장의 ‘미분류’)에서 명사를 뽑아(한국어 형태소 분석기 Kiwi 사용), 갑자기 많이 나오는 단어를 찾습니다.

비율 = (최근 7일 등장 수 ÷ 7 + 0.1) ÷ (이전 28일 등장 수 ÷ 28 + 0.1)
조건: 최근 7일 5번 이상 등장 그리고 비율 ≥ 4
제외: 이미 사전에 있는 굿즈 별칭, 판매 문구(정품·무료배송…), 색상·크기, 아티스트·캐릭터 이름
예 (설명용 숫자): ‘말랑이’가 최근 7일 50번, 이전 28일 10번 등장 → (50÷7 + 0.1) ÷ (10÷28 + 0.1) = 7.24 ÷ 0.46 = 15.8배 → ‘새로 뜨는 단어’에 표시
설계 이유 — 상품은 한 번만 세고(같은 상품이 매일 보여도 처음 본 날 1번) 글은 등장한 날 셉니다. ‘+0.1’은 평소 0번이던 단어가 1~2번 나왔다고 무한대 비율이 되는 것을 막습니다. ‘5번 이상’은 우연히 한두 번 나온 단어를 거릅니다. 아티스트·캐릭터 이름은 ‘굿즈 종류’가 아니므로 무시 목록으로 뺍니다.

새 아이템이 정식 순위에 들어가는 과정

  1. ‘말랑이’ 같은 단어가 화면의 🆕 새로 뜨는 단어에 나타납니다.
  2. 사람이 확인합니다 — 진짜 굿즈 종류인가? (예: 젤리캣은 인형 브랜드 → ‘인형’의 별칭으로, 레고는 새 종류로)
  3. 사전(processing/dictionaries.py)에 한 줄 추가합니다. 아니면 무시 목록에 넣어 다시 안 뜨게 합니다.
  4. 다음 집계부터 해당 상품·글이 그 종류로 분류되어 7가지 신호와 핫지수 순위에 포함됩니다.
  5. 보관된 과거 기록도 다시 분류되므로(같은 상품이 다시 수집될 때 종류가 갱신됨), 추세가 자연스럽게 이어집니다.
왜 자동으로 추가하지 않나? ‘요즘’, ‘텔레토비’처럼 굿즈 종류가 아닌 단어도 갑자기 늘 수 있습니다. 잘못 추가되면 순위가 오염되므로, 발견은 기계가 빠르게 하고 확정은 사람이 하도록 나눴습니다(일주일에 5분 정도).

  • 핫지수 / 순위 / 최근 7일 언급 수 / 근거 신호 수
  • 핫지수 추이 그래프 — 날짜별 점수. 점선 50 = 평소. 손가락·마우스를 대면 그날 값 표시, ‘표로 보기’ 제공
  • 왜 이 점수인가 — 빨강(올림)·파랑(내림) 막대, 합계 = 핫지수 − 50
  • 요즘 순위가 높은 상품 목록
읽는 요령 — ① 핫지수가 높아도 근거 수가 1~2개면 아직 확신하기 이릅니다. ② 추이 그래프가 며칠째 오르는지가 하루 점수보다 중요합니다. ③ ‘언급량’만 오르고 ‘베스트 점유율’이 안 오르면 “말은 많은데 아직 안 팔린다” → 곧 팔릴 수도, 반짝일 수도 있습니다.

화면은 폰·컴퓨터 화면 크기에 맞춰 자동 배치되고, 기기 설정에 따라 다크 모드로도 보입니다. 아이폰은 Safari ‘공유 → 홈 화면에 추가’, 안드로이드는 Chrome ‘⋮ → 홈 화면에 추가’로 앱처럼 쓸 수 있습니다.

멈추지 않게 하는 장치

상황대응
GitHub 예약 실행이 늦거나 빠짐하루 8번(2시간 간격) 시도, 먼저 도착한 1번만 수집
사이트가 봇을 막음연속 3번 실패하면 그 사이트만 그날 포기, 나머지는 계속
사이트가 응답 없이 멈춤요청당 15초, 사이트당 10분, 수집 단계 25분 제한
사이트 구조가 바뀜수집량이 평소 30% 아래로 떨어지면 경고. 직접 설정한 사이트는 ‘자동 패턴 찾기’로 대신 수집 시도
하루 여러 번 수집됨같은 글은 한 번만 저장, 점유율은 회차 평균 → 점수 부풀림 없음

보안

  • DB 비밀번호는 GitHub 비밀값과 Vercel 환경변수에만 있고, 코드·화면·브라우저로 나가지 않습니다.
  • Supabase의 모든 표에 RLS(행 수준 보안)를 켜, 공개 키로는 데이터를 읽거나 바꿀 수 없습니다.
  • 커뮤니티 글은 제목·시각·반응 수만 저장하고 작성자 닉네임·IP는 저장하지 않습니다.
  • robots.txt가 금지한 페이지는 수집하지 않고, 봇 차단(방화벽·보안 검사)을 우회하지 않습니다.

12한계와 앞으로의 계획

정직하게 알려드려야 할 현재의 한계입니다.

① 처음 2주는 점수가 부풀 수 있습니다. ‘평소’를 정의할 이전 28일 데이터가 아직 없어, 처음 잡힌 증가가 모두 급상승처럼 보입니다(서비스 시작: 2026-11-17). → 과거 데이터가 충분히 쌓이기 전에는 해당 신호를 점수에서 빼도록 개선 예정.
② 중요도(1.5, 1.2 …)와 핫지수 기준(85점 = 급상승)은 상식으로 정한 초기값입니다. 아직 데이터로 검증되지 않았습니다. → 몇 달 뒤 “실제로 유행한 종류”를 기준으로 다시 맞춤.
③ 신호 7개 중 4개만 실제로 들어옵니다. 품절·리뷰·판매처 신호는 해당 정보를 주는 소스가 필요합니다. → 쿠팡·네이버 쇼핑 키 발급, 품절 표시가 있는 쇼핑몰 추가.
④ 국내 일부 사이트만 봅니다. 중고나라·더쿠·번개장터는 접근 제한으로 제외됐고, 디시 아이돌 갤러리 일부는 굿즈 글이 적습니다.
⑤ 이용약관. robots.txt는 지켰지만 각 사이트의 이용약관은 별도로 검토하지 않았습니다. 다른 사람에게 공개하거나 상업적으로 쓰려면 각 사이트 약관 확인이 필요합니다.
